# House style

A second sample, so you can see multiple files resolve in one report. Rules
here are illustrative — replace them with your own.

- Match the surrounding code. Comment density, naming, and idiom come from the
  file being edited, not from a general preference.
- Prefer the smallest change that fully solves the problem. A refactor that was
  not asked for is scope, not helpfulness.
- When a test fails, report the failure with its output. Never describe work as
  passing that has not been run.
